# 金山表单（KDocs）Webhook 配置指南

金山表单提交后自动创建抽奖码并给参与者发送通知邮件——原「独立 Python 中间件 +
Power Automate」方案已内嵌为本系统的一个 Webhook 端点，无需单独部署任何服务。

```text
金山表单提交 ──POST──▶ lottery-tool /webhook/.../kdocs
                        ├─ 解析答案（按 qid 提取姓名/学号/手机/邮箱）
                        ├─ 学号 → 抽奖码（校验格式与配额，重复幂等跳过）
                        └─ 系统邮件通道 → 参与者邮箱（报名成功 + 抽奖码）
```

## 前置条件

- 已创建活动，且**活动抽奖码格式与学号位数一致**（如 8 位学号选 `8_digit_number`）——
  格式不符的提交会被拒绝（400），这是最常见的接入问题
- 如需邮件通知：超级管理员已在「系统设置 → 邮件通道」配置可用的 webhook
  （email-poster POST 形式，无 SMTP）
- 金山表单中各题目的 **qid** 可查看（见下文「查找题目 qid」）

## 第一步：活动侧配置

活动编辑页底部「金山表单接入」区块：

| 配置                        | 说明                                               | 默认               |
| --------------------------- | -------------------------------------------------- | ------------------ |
| 姓名/学号/手机号/邮箱题 qid | 表单题目标识到字段的映射，留空用默认值             | 原对接表单的 qid   |
| 绑定码                      | **表单绑定验证必填**：填入表单配置界面显示的绑定码 | 空（无法完成绑定） |
| 报名成功邮件通知            | 提交创建抽奖码后发通知邮件                         | 开                 |

学号将作为抽奖码存储，姓名/手机号/邮箱存入参与者信息。

## 第二步：获取端点地址

活动详情页「Webhook 接入」卡片 → **金山表单端点**一行 → 复制。

地址形如（token 已内嵌在 URL 中，无需请求头）：

```text
https://你的服务域名/webhook/activities/<webhook_id>/kdocs?token=<webhook_token>
```

端点地址按你访问管理面板的实际来源自动推导（部署后即为线上域名，无需额外配置）；
如需强制固定，可设置环境变量 `BASE_URL`（优先级最高）。

Token 泄露或轮换需求：同一卡片「重新生成 Token」，旧地址立即失效（需同步更新表单侧
配置）。系统日志中的 token 查询参数会自动脱敏为 `token=***`。

## 第三步：金山表单侧配置（绑定验证）

1. 在金山表单的设置中开启**数据推送 / Webhook**（入口以实际界面为准，通常在表单设置的
   扩展或推送类目下），将上一步复制的完整地址粘贴为接收 URL，格式选 JSON
2. 表单会立即向该地址发送**绑定验证请求**（一条完整的样例提交），并显示它要求的绑定码
   （形如 `20260808191114591122362`）
3. 把该绑定码填入活动编辑页「金山表单接入 → 绑定码」并保存——系统此后会在响应中
   带上 `{"bind_code":"..."}`（HTTP 200），表单侧即显示绑定成功
4. 绑定成功后，表单收集到的数据将以 JSON 实时推送到该地址；
   绑定样例提交会创建一条抽奖码，建议在码列表中清理

> 绑定码同时会在每次成功创建抽奖码的响应中原样带回。

## 查找题目 qid

题目 qid 是金山表单内部对每道题的固定标识（如 `k9ce0p`），出现在 webhook 推送的
`answerContents` 里。两种获取方式：

1. 先把端点配好并提交一条数据，从服务日志或下方 curl 自查返回/载荷中的 `qid`
2. 在金山表单编辑器中查看题目属性（部分版本直接展示题目 ID）

拿到 qid 后回到第一步，在活动编辑页填入对应输入框即可。

## Webhook 契约

### 请求（金山表单 → 本系统）

```json
{
   "event": "create_answer",
   "formId": "form-001",
   "answerContents": [
      { "qid": "k9ce0p", "title": "姓名｜Name", "value": "张三" },
      { "qid": "br1kvx", "title": "学号｜Student ID", "value": "20230001" },
      { "qid": "30f4xe", "title": "UNNC邮箱｜UNNC Email", "value": "zhangsan@unnc.edu.cn" },
      { "qid": "7wpvum", "title": "手机号｜Telephone Number", "value": "13800138000" }
   ]
}
```

- 仅处理 `event: "create_answer"`；其他事件返回 200 但不处理
- 姓名、学号必填（缺失返回 400 并指明缺失字段）；手机号、邮箱尽力提取
- 值为数组时取第一项（单选题）；首尾空白自动去除
- 鉴权：URL 中的 `?token=`，或 `Authorization: Bearer <token>` 请求头
- **绑定验证**：`GET` 该地址（或配置了绑定码时的非提交 POST）返回
  `{"bind_code":"..."}`，供金山表单完成 URL 绑定

### 响应

| 场景                                        | 状态码 | 响应                                                                                     |
| ------------------------------------------- | ------ | ---------------------------------------------------------------------------------------- |
| 绑定验证（GET / 非提交 POST，已配绑定码）   | 200    | `{ "bind_code": "..." }`                                                                 |
| 绑定验证但未配置绑定码                      | 400    | 提示在活动编辑页配置绑定码                                                               |
| 创建成功                                    | 200    | `{ "bind_code": "...", "data": { "code": "...", "created": true } }`（bind_code 在顶层） |
| 重复提交/表单重试                           | 200    | `{ "bind_code": "...", "data": { "code": "...", "created": false } }`（幂等）            |
| 非 create_answer 事件（未配绑定码）         | 200    | `{ "message": "事件已接收但未处理" }`                                                    |
| 缺姓名/学号、学号格式不符活动码格式、超配额 | 400    | `error.details` 说明具体原因                                                             |
| Token 错误/缺失                             | 401    | 标准错误响应                                                                             |

> 「检验并绑定」实际是金山发来一条**完整的 create_answer 样例提交**（即上表「创建成功」行），
> 要求 HTTP 200 且响应含 `bind_code`——这就是绑定码必填的原因。样例提交会真实创建一条
> 抽奖码，绑定成功后建议在码列表中清理该样例数据。

邮件发送失败只记日志，不影响提交结果（参与者仍成功报名）。

## 测试与排障

端点可直接用 curl 模拟（`WEBHOOK_URL` 即第二步复制的地址）：

```bash
curl -X POST "$WEBHOOK_URL" \
  -H "Content-Type: application/json" \
  -d '{"event":"create_answer","answerContents":[{"qid":"k9ce0p","value":"张三"},{"qid":"br1kvx","value":"20230001"}]}'
```

| 现象                 | 排查                                                                                         |
| -------------------- | -------------------------------------------------------------------------------------------- |
| 表单绑定验证失败     | 活动未配置绑定码，或与表单显示的不一致——按「第三步」重新复制粘贴                             |
| 400 提到「格式」     | 活动抽奖码格式与学号位数不一致——改活动格式或确认学号题 qid 映射正确                          |
| 400 缺少必要字段     | qid 映射与表单实际题目不匹配——核对「查找题目 qid」                                           |
| 401                  | Token 已被重新生成，或 URL 复制不完整——回详情页重新复制                                      |
| 报名成功但没收到邮件 | 邮件通道未配置 / 通知开关已关 / 表单里没填邮箱题——看服务日志有无「金山表单通知邮件发送失败」 |
| 想确认推送内容       | 服务日志会打印（token 已脱敏）；或临时把端点指向自己的接收服务观察载荷                       |
